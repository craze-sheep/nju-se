# 1.0 软件开发流程

## 目标

1.0 版本只实现一个最简易的 coding agent，用来证明项目核心闭环成立：

用户输入任务 -> 程序调用大模型原生 tool calling -> 程序执行本地工具 -> 把结果返回给大模型 -> 输出最终结果。

## 开发原则

- 先文档，后代码。
- 先测试，后实现。
- 每完成一个小阶段就提交一次，让老师能从 Git 历史看到开发过程。
- 不使用 LangChain、LlamaIndex、AutoGen、OpenAI Agents SDK 等 agent 框架。
- 只使用模型厂商 API 客户端库和模型原生 tool calling 接口。
- API key 只从环境变量或不入库配置读取，不能写进仓库。
- 1.0 只做最小闭环，不追求功能复杂。

## 1.0 不做什么

- 不做网页界面。
- 不做多智能体。
- 不做长期记忆。
- 不做自动 git 提交。
- 不做复杂权限系统。
- 不做插件系统。

## 阶段 1：写需求文档

文件：`1.0/doc/requirements.md`

写清楚：

- 1.0 要实现的功能。
- 1.0 暂时不实现的功能。
- 运行方式。
- 安全边界。
- 验收标准。

建议提交：

```bash
git add 1.0/doc
git commit -m "docs: define 1.0 requirements"
git push
```

## 阶段 2：写实现计划

文件：`1.0/doc/plan.md`

把任务拆成小块：

1. 项目结构和 Python 包入口。
2. 本地工具：列目录、读文件、写文件、执行命令。
3. 模型调用封装。
4. agent 主循环。
5. 命令行入口。
6. README 和演示准备。

建议提交：

```bash
git add 1.0/doc/plan.md
git commit -m "docs: add 1.0 implementation plan"
git push
```

## 阶段 3：先实现本地工具

先写测试文件：`1.0/tests/test_tools.py`

测试内容：

- `list_files` 能列出目录文件。
- `read_file` 能读取文件内容。
- `write_file` 能写入文件。
- `run_command` 能执行简单命令。
- 路径不能越过项目工作目录。
- 命令执行有超时限制。

开发顺序：

```text
写一个测试 -> 运行并确认失败 -> 写最小实现 -> 运行并确认通过 -> 记录日志 -> 提交
```

建议验证命令：

```bash
PYTHONPATH=1.0/src pytest 1.0/tests/test_tools.py -q
```

建议提交：

```bash
git add 1.0/src 1.0/tests 1.0/doc/log.md
git commit -m "feat: add local tool helpers"
git push
```

## 阶段 4：实现模型调用封装

文件：`1.0/src/nju_agent/llm.py`

目标：

- 从环境变量读取模型配置。
- 支持 `OPENAI_API_KEY`。
- 支持可选的 `OPENAI_BASE_URL`。
- 支持可选的 `OPENAI_MODEL`。
- 不在代码里写死密钥。

建议验证：

```bash
PYTHONPATH=1.0/src pytest 1.0/tests -q
```

建议提交：

```bash
git add 1.0/src 1.0/tests 1.0/doc/log.md
git commit -m "feat: add llm client wrapper"
git push
```

## 阶段 5：实现 agent 主循环

文件：`1.0/src/nju_agent/agent.py`

主循环负责：

- 保存对话历史。
- 把任务发给模型。
- 解析模型要求调用的工具。
- 执行本地工具。
- 把工具结果再返回给模型。
- 最多运行固定轮数，例如 10 轮。
- 模型给出最终答案后退出。

建议先用假的模型对象写测试，避免每次测试都消耗真实 API。

建议提交：

```bash
git add 1.0/src 1.0/tests 1.0/doc/log.md
git commit -m "feat: add minimal agent loop"
git push
```

## 阶段 6：实现命令行入口

文件：`1.0/src/nju_agent/__main__.py`

目标运行方式：

```bash
PYTHONPATH=1.0/src python -m nju_agent "创建一个 hello.py 并运行它"
```

命令行需要打印：

- 用户任务。
- 每次工具调用。
- 工具返回结果。
- 最终回答。

建议提交：

```bash
git add 1.0/src 1.0/tests 1.0/doc/log.md
git commit -m "feat: add command line entry"
git push
```

## 阶段 7：准备演示和 README

演示任务建议：

```text
请创建一个 Python 文件 hello.py，让它打印 hello nju，然后运行它确认结果。
```

README.txt 需要包含：

- Git 仓库地址。
- 环境准备方式。
- API key 配置方式。
- 运行命令。
- 1.0 特色功能。

建议提交：

```bash
git add README.txt 1.0/doc
git commit -m "docs: prepare 1.0 demo instructions"
git push
```

## 1.0 验收标准

- 能通过命令行启动。
- 至少有文件工具和命令工具。
- 至少有一个 agent 循环。
- 测试能跑通。
- README 能指导别人运行。
- Git 历史能看出从文档、测试到实现的过程。
