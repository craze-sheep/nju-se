# 1.0 需求说明

## 项目背景

本项目要实现一个简化版 coding agent。它不是自己训练一个 AI，而是写一个程序，让 DeepSeek 这类大模型可以通过本地工具完成编程任务。
实现方式只使用模型厂商 API 客户端库和原生 tool calling，不依赖现成 agent 框架。

## 1.0 目标

1.0 版本只做最小闭环：

```text
用户进入对话 -> 调用大模型 -> 模型请求工具 -> 本地执行工具 -> 返回工具结果 -> 模型给出回答
```

## 必须实现的功能

- 命令行入口：用户可以在终端进入交互式对话。
- 搜索工具：可以按关键词搜索工作目录内的文本文件和路径，返回命中的文件、行号和片段。
- 文件列表工具：可以查看工作目录里的文件。
- 读文件工具：可以读取工作目录内的文本文件。
- 写文件工具：在可写权限下可以创建或修改工作目录内的文本文件。
- 执行命令工具：在可写权限下可以运行简单命令并返回输出。
- Agent 循环：可以把模型输出、工具结果和历史消息串起来。
- 会话级权限控制：默认只读，用户可通过 `/access` 切换为可写；只读时开放 `search` / `list_files` / `read_file`。
- 可选轻量 subagent 分工：用户可通过 `/subagents` 打开 planner / reviewer；两者只提供建议，不拥有工具权限。
- 最大轮数限制：避免程序无限循环。
- 基础错误处理：工具失败时返回错误信息，而不是直接崩溃。

## 暂不实现的功能

- 不做网页界面。
- 不做长期记忆。
- 不做完整多智能体编队或多个执行者。
- 不做自动提交代码。
- 不做复杂权限系统，只做会话级只读 / 可写切换。
- 不使用 LangChain、LlamaIndex、AutoGen、OpenAI Agents SDK 等 agent 框架。

## 安全边界

- API key 不写入代码、README 或视频。
- API key 只从环境变量读取，默认使用 `DEEPSEEK_API_KEY`。
- 文件工具只能访问工作目录内的文件。
- 命令执行要有超时限制，默认本地执行。
- 只读会话不能调用写文件或执行命令工具，但可以使用搜索、列目录和读文件工具。
- planner / reviewer 不暴露任何工具；executor 仍是唯一执行工具调用的角色。
- 1.0 版本默认对危险命令先确认再执行，例如删除文件、格式化磁盘、修改系统配置。

## 运行目标

最终希望可以运行：

```bash
DEEPSEEK_API_KEY=... PYTHONPATH=1.0/src python -m nju_agent
```

程序应展示大致过程：

```text
用户任务：创建一个 hello.py，让它打印 hello nju，然后运行它
工具调用：write_file
工具调用：run_command
最终结果：hello.py 已创建并成功运行
```
